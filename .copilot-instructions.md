### Branch Strategy
- **`master`** - Production code (stable, do not modify)

- No incremental deployment; single cutover when complete

### Current Architecture
```

├── Django 4.2 + Templates + jQuery + Bootstrap 3
```

## Code Generation Guidelines

### Backend (Python/Django)
```python
# ✅ DO: Modern Django 5.1 patterns
from rest_framework import viewsets
from rest_framework.permissions import IsAuthenticatedOrReadOnly

class RaceViewSet(viewsets.ModelViewSet):
    queryset = Race.objects.select_related('club', 'location')
    serializer_class = RaceSerializer
    permission_classes = [IsAuthenticatedOrReadOnly]

# ❌ DON'T: Template views
from django.views.generic import ListView
class RaceListView(ListView):  # Don't create these
    template_name = 'races.html'  # No templates!
```

## Common Questions

### "Should I add a template view?"
❌ No. We're removing all template views. Suggest an API endpoint instead.

### "Should I use jQuery for this?"
❌ No. We're removing jQuery. Suggest React component instead.

### "Can I update something in master branch?"
❌ No, unless it's a critical production bug. All development is on `modernization` branch.

### "Should I maintain backward compatibility?"
❌ No. We're doing a complete rewrite. No need for backward compatibility during development.

### "What version of Django should I target?"
✅ Django 5.1 LTS - always use latest patterns.
