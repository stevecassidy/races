## File Structure to Maintain

> **The legacy `races/apps/cabici/api.py` is frozen.** It is not extended and not
> adapted — Phase 2 rebuilds the API from an OpenAPI contract and then deletes it.
> **The race-day client is now in this repo** (`frontend/apps/raceday`, vendored
> from `stevecassidy/cabici-raceday-react`), so its contract is **co-designed,
> not frozen** — but it is the highest-risk surface in the app and currently
> loses data (D1/D2/D3 in [MODEL_REVIEW.md](MODEL_REVIEW.md)).
> Monorepo decision and rationale: [MODEL_REVIEW.md](MODEL_REVIEW.md).

## Common Questions

### "Should I add a template view?"

❌ No. We're removing all template views. Suggest an API endpoint instead.

### "Should I use jQuery for this?"

❌ No. We're removing jQuery. Suggest React component instead.

### "Can I update something in master branch?"

❌ No, unless it's a critical production bug. All development is on `modernization` branch.

### "Should I maintain backward compatibility?"

❌ No. We're doing a complete rewrite. No need for backward compatibility during development.

### "What version of Django should I target?"

✅ Django 5.2 - always use latest patterns.
